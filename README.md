# دارونیک — نسخه نمایشی برای cPanel

این مخزن شامل فایل اصلی `darunik-complete-project.zip` و نسخه اصلاح‌شده سورس در پوشه `darunik` است. نسخه اصلاح‌شده برای نمایش نمونه‌کار در آدرس زیر به خروجی استاتیک تبدیل شده است:

**https://demo.ariagh.ir/daroonik/**

این پروژه قالب یا افزونه وردپرس نیست؛ فایل‌های خروجی آن مستقیماً از هاست نمایش داده می‌شوند. اجرای نسخه آماده روی cPanel به Node.js، پایگاه داده یا SSH نیاز ندارد. فایل ZIP اصلی را نباید از صفحه نصب پوسته یا افزونه وردپرس نصب کرد.

## امکانات و محدودیت نسخه نمایشی

- صفحه‌ها، عکس‌ها، فونت‌ها و CSS از مسیر `/daroonik` بارگذاری می‌شوند.
- جستجو، فیلتر، سبد خرید، علاقه‌مندی و مقایسه در مرورگر کار می‌کنند.
- سفارش صرفاً آزمایشی است و فقط در همان مرورگر ذخیره می‌شود؛ با پاک‌شدن داده‌های مرورگر از بین می‌رود. پرداخت و ارسال واقعی وجود ندارد.
- فرم‌های تماس و خبرنامه فقط ظاهر و تعامل نمایشی دارند؛ پیام یا عضویتی به سرور ارسال نمی‌کنند.
- این نسخه به کاربران، محصولات یا سفارش‌های وردپرس و ووکامرس متصل نیست. برای فروش واقعی و اتصال به ووکامرس، توسعه جداگانه لازم است.
- برای تست فرم‌ها از اطلاعات ساختگی استفاده کنید.

## نصب فایل ZIP آماده در cPanel

> نسخه آماده فقط برای مسیر دقیق `/daroonik` ساخته شده است. اگر پوشه را تغییر نام دهید یا در مسیر دیگری بگذارید، لازم است پروژه مجدداً با مسیر جدید ساخته شود.

1. **پشتیبان تهیه کنید.** از فایل‌ها و پایگاه داده وردپرس فعلی و همچنین محتوای احتمالی مقصد یک نسخه پشتیبان بگیرید. اگر از محل سایت مطمئن نیستید، پیش از تغییر از پشتیبانی هاست راهنمایی بگیرید.
2. وارد **cPanel → Domains** شوید و در فهرست، `demo.ariagh.ir` را پیدا کنید. ستون **Document Root** پوشه اصلی همین زیردامنه را نشان می‌دهد. آن را یادداشت کنید؛ ممکن است برای هر هاست متفاوت باشد و الزاماً `public_html` نیست.
3. اگر زیردامنه در فهرست وجود ندارد، از طریق **Create a New Domain** یا بخش **Subdomains** در نسخه‌های قدیمی cPanel آن را بسازید. مسیر پیشنهادی cPanel را بررسی کنید و بدون اطلاع، Document Root سایت اصلی را تغییر ندهید. اگر DNS دامنه خارج از این هاست مدیریت می‌شود، درباره رکورد `demo` با پشتیبانی هماهنگ کنید.
4. در **SSL/TLS Status** بررسی کنید برای `demo.ariagh.ir` گواهی معتبر فعال باشد. در صورت پشتیبانی هاست، **Run AutoSSL** را اجرا کنید؛ صدور گواهی به تنظیمات DNS و هاست بستگی دارد.
5. به **Files → File Manager** بروید و دقیقاً پوشه Document Root زیردامنه `demo.ariagh.ir` را باز کنید. داخل آن پوشه‌ای با نام دقیق `daroonik` بسازید. اگر از قبل پوشه یا سایت مهمی با همین نام وجود دارد، چیزی را بازنویسی نکنید؛ ابتدا پشتیبان بگیرید و مقصد را بررسی کنید.
6. پوشه `daroonik` را باز کنید. گزینه **Upload** را بزنید و ZIP آماده خروجی استاتیک را انتخاب کنید؛ ZIP اصلی پروژه را آپلود نکنید.
7. پس از تکمیل آپلود، در همان پوشه روی ZIP راست‌کلیک و **Extract** را انتخاب کنید. محتوای ZIP باید مستقیماً داخل `daroonik` قرار گیرد، نه یک پوشه اضافی داخل آن. بررسی کنید این موارد کنار هم دیده شوند:

   ```text
   document-root-of-demo.ariagh.ir/
   └── daroonik/
       ├── index.html
       ├── _next/
       ├── images/
       ├── fonts/
       ├── shop/
       ├── product/
       └── ...
   ```

   مسیر بالا نمونهٔ ساختار است؛ نام و محل Document Root را از پنل خودتان بردارید. برای استخراج حدود ۵۰ مگابایت فضای خالی، علاوه بر فضای فایل ZIP، و ظرفیت کافی برای تعداد فایل‌ها در نظر بگیرید.
8. آدرس `https://demo.ariagh.ir/daroonik/` را باز کنید. سپس `https://demo.ariagh.ir/daroonik/shop/` و یکی از صفحات محصول را هم مستقیماً باز و تازه‌سازی کنید. با موبایل، منو، جستجو، فیلتر و سبد را امتحان کنید.
9. در صورت اطمینان از استخراج، می‌توانید فقط ZIP آپلودشده را از داخل پوشه مقصد حذف کنید؛ فایل‌های استخراج‌شده را حذف نکنید. حذف ZIP الزامی نیست.

### اگر نمایش درست نبود

- **۴۰۴:** ابتدا Document Root زیردامنه و وجود `daroonik/index.html` را کنترل کنید؛ مطمئن شوید فایل‌ها داخل پوشه اضافی قرار نگرفته‌اند. ساختار `shop/index.html` هم باید موجود باشد.
- **صفحه بدون ظاهر یا عکس:** نام پوشه باید دقیقاً `daroonik` و فایل‌های `_next`، `images` و `fonts` در کنار `index.html` باشند. کش مرورگر و کش هاست/CDN را پاک کنید.
- **۴۰۳:** سطح دسترسی و تنظیمات سرور را با پشتیبانی هاست بررسی کنید. مقادیر معمول پوشه‌ها `755` و فایل‌ها `644` هستند.
- **مشکل SSL یا بازنشدن زیردامنه:** ابتدا DNS و وضعیت AutoSSL را با پشتیبانی هاست بررسی کنید.
- **صفحه اصلی می‌آید ولی صفحه‌های داخلی بعد از تازه‌سازی ۴۰۴ می‌شوند:** وجود پوشه صفحه و `index.html` آن را بررسی کنید و از پشتیبانی بخواهید تنظیمات DirectoryIndex و قوانین بازنویسی زیردامنه را بررسی کند. فایل `.htaccess` یا تنظیمات وردپرس اصلی را بدون شناخت تغییر ندهید.

در صورت نیاز می‌توانید از پیشخوان وردپرس، یک **پیوند سفارشی** به آدرس کامل نمونه‌کار در منوی سایت اضافه کنید. محتوای این نسخه به‌صورت خودکار در برگه‌ها یا مدیریت محصولات وردپرس ظاهر نمی‌شود.

## ساخت دوباره خروجی از سورس

فقط برای زمانی که سورس را تغییر داده‌اید: روی رایانه توسعه Node.js 22 و npm نصب کنید، سپس:

```bash
cd darunik
npm ci
npm run typecheck
npm run lint
npm run build
npm run test:export
npm run start
```

پیش‌نمایش محلی در `http://localhost:3000/daroonik/` است. `npm run start` فقط یک سرور پیش‌نمایش است؛ برای cPanel، محتویات پوشه `darunik/out` را ZIP کنید، نه خود پوشه `out` یا سورس را. پس از هر تغییر در کد باید خروجی را دوباره بسازید و فایل‌های جدید را جایگزین نسخه قبلی کنید. خروجی تولیدشده، وابستگی‌ها و فایل‌های محیطی عمداً در Git ذخیره نمی‌شوند.
